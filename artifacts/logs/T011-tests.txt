### FIRST INCONSISTENCY #1 — `facts` (SlotFact) coverage definition (spec ambiguity)
- Minimal Golden input (G02, strategy REPEAT_VALUE):
  <table><thead><tr><th>名称</th><th>数量</th></tr></thead><tbody><tr><td>苹果</td><td>3</td></tr></tbody></table>
  TS value: buildSlotFacts / analyze().facts has 2 entries (TD-occupied slots
  only: c02 苹果, c03 3).
  Oracle value: golden_expected.json G02 expected.facts has 4 entries (one per
  slot: c00 名称, c01 数量, c02 苹果, c03 3 — including the two thead TH slots).
  First differing field: facts: length differs (expected 4, got 2).
  Vitest: Golden 'G02' > facts match the hand computation — FAIL.
- Minimal property input (seed 0, 7x6, 19 DOM cells; full HTML in the
  generator — reproduce with generateTable(0); first rows:
  <table><thead><tr><th colspan="2">c\d</th><th colspan="3">A &amp; B</th>
  <th scope="col">A &amp; B</th></tr> ... </thead><tbody> ... </tbody></table>):
  TS value: 24 facts (TD-occupied slots only).
  Oracle value: 42 facts (one per slot, 7 rows x 6 cols, including TH slots).
  First differing field: facts: length differs (expected 42, got 24).
  Vitest: seed 0 — FAIL. (Lowest failing seed; 181 of 200 seeds fail on this
  same field, and the 19 agreeing seeds are exactly the all-TD tables with no
  TH cell at all — where the two definitions coincide.)
- Scope of the divergence: 24 of 48 Goldens fail ONLY on `facts`
  (G02, G03, G04, G06, G07, G08, G09, G10, G12, G14, G16, G17, G19, G20, G21,
  G22, G24, G25, G26, G29, G30, G31, G39, G40 — every Golden containing at
  least one TH cell; the 16 all-TD success Goldens + 8 error Goldens pass
  fully). 181 of 200 property seeds fail ONLY on `facts`. All other compared
  fields — rows, cols, slotOwner, cells, handover, f_origin, f_repeat,
  witness status/source_cell_id/split_cost/header_association_changed/
  collision_kind, a/b/markdown SHA-256, F(B), B cells, B slotOwner, error
  codes — agree on all 48 Goldens and all 200 seeds.
- Root cause (read from the code, not guessed): TS src/core/records.ts
  buildSlotFacts skips non-TD cells ("只对 role 为 TD 的单元格占用的槽位出
  记录；th 槽位不出事实行（th 是标题本身，不是数据值）"); Oracle
  oracle/reference.py build_facts appends one fact per slot for every slot
  regardless of role, while its handover_lines filters to TD afterwards
  ("One line per td-occupied slot (spec 5.4)"). So the two sides agree on
  the handover text (TD-only, 40/40 Golden handover tests pass) and disagree
  only on what the `facts` array itself contains.
- Classification: SPEC AMBIGUITY (plan §9.3), not a proven bug on either side
  yet. The frozen spec does not pin SlotFact coverage: §5.4 says the handover
  text is "对每个 td 占用的槽位", and §2.1 G04 says "逐数据格输出行/列显式
  表头路径" — both point to TD/data-cell-only records, which is the TS
  reading. No frozen sentence says `facts` must cover TH-occupied slots.
- Recommended fix (for the coordinator's new card, NOT done here — oracle/*
  and src/core/* are outside this card's write scope): rule in favour of
  TD-only (spec §5.4 + G04), narrow Oracle build_facts to TD-occupied slots
  (the same filter handover_lines already applies), and drop the TH-slot
  entries from the hand-computed `facts` arrays in golden_expected.json
  (handover lines are unchanged by this — they are already TD-only).
  Alternative ruling (widen TS buildSlotFacts to all slots) would instead
  change analyze().facts and the UI's per-slot display; either way the ruling
  must be written down first, then one side fixed, then this card re-run
  (T011 tests are kept failing until then — they are the regression net).
- What was NOT done: no skip / expected-fail / todo marker was added; no
  expectation was back-filled from TS output (golden expectations are still
  exactly the T006 hand values); no core/oracle file was modified to make the
  tests pass; the `facts` comparison was NOT dropped from either suite.
