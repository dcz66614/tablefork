## 6. CRLF / LF behaviour (summary of §5 + the tests)
- flatten.ts itself only ever emits LF (`\n` joins + one trailing LF); it
  never emits CR, because it builds lines from already-normalised grid text.
- CRLF can only reach flatten through cell text, and parse.ts
  (normalizeCellText) folds CR/LF/CR-LF inside cells to a single U+0020
  before grid construction — verified by E8 and by the CRLF/CR tests in
  tests/core/t004-temp.test.ts. No `\r` survives into any output above.

## 7. Documented judgement calls (spec does not pin these down; see flatten.ts header)
J-T004-1. Trailing newline: §5.1 "最后统一 LF 换行" is read as "every
    generated line is LF-terminated", i.e. the output ends with a single LF
    after the last row. The §6.3 byte-exact test pins this reading. If T011 /
    the independent Oracle rule the other way ("lines joined by LF, no
    trailing newline"), the fix is one line (`lines.join('\n')`); until then
    this reading is the frozen behaviour. This is the most consequential
    call in this card — it decides byte equality in T007 compare and T005
    witness, so it needs T011 / final-review confirmation.
J-T004-2. Empty-value cells: an empty origin cell and an empty ORIGIN_EMPTY
    extension slot are indistinguishable in output (`|  |`). That is the
    information loss §5.1 defines for F, not a defect of this module.
J-T004-3. Separator row: fixed `---` per column, inserted after row 1
    regardless of section (thead/tbody); §5.1 says "after row 1" with no
    section qualifier.
J-T004-4. Escape scope: only `\` and `|` are escaped; `*`, `_`, backtick,
    `#` etc. are left as-is (§5.1 freezes only these two).
J-T004-5. flatten.ts does NOT re-normalise whitespace: cell text arrives
    already normalised from parse.ts (§5.1: newline handling is an
    extraction-stage matter). A hand-built GridResult carrying a raw `\r`
    or `\n` in cell text would pass it through escaped only for `\`/`|`;
    all real grids come from parseValidatedTable + buildGrid, so this
    cannot occur through the pipeline.
