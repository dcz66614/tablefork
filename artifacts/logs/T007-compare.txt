## 7. GFM subset detection rules (detectGfmPipeTable)
A "pipe row" is a line containing at least one unescaped '|'; cells are split
on unescaped '|' only ('\|' does not split — F escapes cell pipes as \| per
§5.1, so detection must recognise it). Optional leading/trailing '|' are
outer framing, not cells. A delimiter row is a row whose every cell matches
:?-+:? after trimming. A "table block" is a run of contiguous pipe rows.
- SINGLE_PIPE_TABLE: exactly one block, block has ≥2 rows, row 2 is a
  delimiter, every row has the same cell count, and outside the block there
  are only blank lines. rowCount/columnCount are reported.
- MULTIPLE_TABLES: ≥2 blocks each satisfying the table conditions.
- NOT_A_PIPE_TABLE: everything else, with per-line issues (1-based):
  * no pipe rows at all ("M 不含任何 pipe 表行");
  * a block of a single row ("只有一行 pipe 行，缺少分隔行");
  * row 2 not a delimiter ("不是合法分隔行");
  * a row whose cell count differs from the header ("列数 … 与表头列数 … 不一致");
  * non-table text lines outside a table ("非表格文本");
  * one valid table plus other content (extra text or extra non-table blocks).
- Boundary cases (all test-pinned): blank lines split blocks (two blocks
  separated by a blank line are two tables, or non-tables if malformed);
  a table with header + delimiter but zero body rows IS a table (rowCount 2);
  detection trims surrounding whitespace per line for SHAPE classification
  only — the byte comparison never trims anything (J-T007-5).
- Detection never rewrites the input and never normalizes: CRLF line
  endings are handled by per-line trim during classification only.

## 8. Documented judgement calls (spec does not pin these down)
J-T007-1. NOT_SUPPLIED: undefined OR '' both mean "未输入 M" (§5.3).
    Rationale: in the UI textarea '' is exactly "nothing pasted", synonymous
    with undefined; calling it EXACT_DIFF would mislead the user into
    thinking input was supplied but mismatched. A whitespace-only string
    (' ', '\n') IS supplied input: it goes through normal comparison
    (EXACT_DIFF + NOT_A_PIPE_TABLE diagnosis). NOT_SUPPLIED reports
    gfm NOT_CHECKED ("M 未提供，未做 GFM pipe 表检测") — absence of input
    is not reported as "not a pipe table".
J-T007-2. Error path: M over 64 KiB UTF-8 (§3.1) throws TableForkInputError
    with code OVER_SIZE (reusing parse.ts fail(); no CompareStatus is
    produced). A non-string canonicalMarkdown / suppliedMarkdown is a
    caller programming error: it throws TypeError, deliberately NOT a
    TableForkError — the 7-code enum only covers HTML table structure
    errors, and misusing one of its codes would mislabel the failure.
    "Invalid input" for compare otherwise means: non-pipe / multi-table /
    ragged M, which is a DIAGNOSIS (NOT_A_PIPE_TABLE / MULTIPLE_TABLES),
    not an exception — M is arbitrary user text, and only the size limit
    and type contract are hard errors.
J-T007-3. Character index = Unicode code-point index (for...of order), not
    UTF-16 unit index; they coincide for BMP text (all CJK in the evidence)
    and differ only for astral characters. Byte offsets come from TextEncoder.
    TextEncoder replaces lone surrogates with U+FFFD by definition — that is
    the platform UTF-8 encoder's behaviour on an ill-formed JS string, not
    a normalization step applied by this module; real pasted/file text is
    well-formed UTF-16. No NFC/NFD, CRLF folding, trim, BOM stripping, or
    trailing-space removal is performed anywhere in this module.
J-T007-4. GFM strictness: ragged body rows (column count ≠ header) are
    reported as NOT_A_PIPE_TABLE, stricter than the GFM spec (which tolerates
    them by padding/ignoring). Rationale: F(A) never emits ragged rows, so a
    ragged M can never equal F(A); flagging it explicitly is more useful
    than silently accepting it as "a table". If T011 / final review wants
    spec-literal tolerance, the change is confined to detectGfmPipeTable.
J-T007-5. Detection trims whitespace only for shape classification; the
    byte comparison is always raw. A line with leading spaces still counts
    as a table row for detection, but its spaces are byte differences in
    comparison (test-pinned: trailing space before LF → EXACT_DIFF at that
    byte).
J-T007-6. Integrity boundary: compare.ts does not import witness.ts and its
    result type has no witness/proof/collision fields (asserted in tests:
    'witness'/'proof'/'collision' not in result). An EXACT_DIFF or a GFM
    diagnosis can never be mistaken for a collision certificate; a
    CERTIFIED_COLLISION claim can only come from witness.ts (T005) via
    analyze() (T008). M ≠ F(A) never implies anything about M vs F(B).
J-T007-7. Worker jobId contract: compareMarkdown is stateless, pure, and
    takes no jobId and returns none — nothing to cache, nothing to go stale.
    jobId lives only in the protocol envelope (src/worker/protocol.ts:
    WorkerRequestMessage / WorkerResponseMessage), which this card does not
    modify. The future Worker ANALYZE handler (T010) will call
    compareMarkdown(payload.suppliedMarkdown, canonical) inside the handler
    and echo the SAME jobId in its RESULT/ERROR reply; the main thread only
    applies results whose jobId matches the latest input version (protocol
    contract, already frozen in T002). No new protocol type was needed, so
    none was created — adding one would have duplicated protocol.ts.
J-T007-8. Remote-URL refusal uses a plain Error, not TableForkError: the
    frozen 7-code enum (types.ts) covers HTML table structure errors only
    (INVALID_SPAN / OVERLAP / RAGGED / OVER_SIZE / NESTED / HEADER /
    CANCELLED); there is no "remote source" code, and reusing OVER_SIZE or
    UNSUPPORTED_* would mislabel the failure. The message names the URL and
    states no request was made.
