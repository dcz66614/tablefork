## 7. Judgement calls (spec does not pin these down; recorded for T011 / final review)
J-T008-1 (witness 'UNSUPPORTED' is never produced by analyze): the task card
  requires invalid input to throw a TableForkError, not to return a result.
  witness.ts J-T005-3 said T008 would map thrown errors to witness
  'UNSUPPORTED'; the card's throw-requirement takes precedence, so analyze()
  lets parse/grid/findWitness errors propagate and 'UNSUPPORTED' is never
  returned. The type still lists it (frozen §6.1); only the Worker/UI layer
  (T010/T009) could map a thrown error to that status, if ever needed.
J-T008-2 (analyze entry-validation error code): the frozen 7-code enum has
  no INVALID_INPUT. Following parse.ts's precedent (non-string html and
  "no <table>" both use INVALID_RAGGED_GRID as the catch-all bucket for
  malformed input, with the message stating the true cause), analyze's own
  schema/strategy/type checks throw code INVALID_RAGGED_GRID with messages
  like `analyze: schema must be "tablefork.input/v1", got ...`. Upstream
  parse/grid/compare errors keep their own codes (e.g. OVER_SIZE for an
  over-long suppliedMarkdown, UNSUPPORTED_NESTED_TABLE for nested tables).
J-T008-3 (proof field when absent): the field is OMITTED entirely from the
  result object (no `proof: undefined` key). JSON.stringify drops undefined
  anyway, so both spellings serialize identically; omission makes
  `'proof' in result === false` an explicit, testable contract. Nailed down
  here and in tests (certified → present; flat → absent before and after
  JSON round-trip).
J-T008-4 (SHARED_SOURCE_CELL has nowhere to live): §3.3 says a td spanning
  slots with differing header paths must be flagged SHARED_SOURCE_CELL, but
  the frozen §6.1 SlotFact has no such field and types.ts is frozen. The
  per-slot records sharing one cellId already express the shared source
  (tested: a rowspan=2 td yields two facts with the same cellId); no extra
  field was invented. If T011/final review wants the flag, it needs a
  spec change to SlotFact, not a silent extension here.
J-T008-5 (hash implementation choice): records.ts computes no hash at all.
  report.ts computes hashes only via WebCrypto (crypto.subtle.digest) —
  never node:crypto — and verifies equivalence with witness.sha256Utf8 by
  running both on the same inputs (§6 table: 5/5 equal, incl. known vectors
  and the 879-byte A graph). analyze() additionally cross-checks the
  WebCrypto re-hash of canonicalMarkdown and the A graph against the
  proof's hashes on every certified call. TextEncoder and node 'utf8'
  agree on lone surrogates (both U+FFFD), so the equivalence is exact.
J-T008-6 (values stay strings): buildSlotFacts copies grid cell text
  verbatim; no Number() / parseInt / JSON-number path exists in records.ts
  or report.ts. Tested with the 17-digit string '12345678901234567':
  value stays exactly that string (Number() would give 12345678901234568).
  splitCost stays a JSON number (it is a structural integer, not cell data).
J-T008-7 (warnings are fixed-order and deterministic): EXACT_DIFF note,
  then NO_WITNESS_FOUND note, then unknown-header count note; no timestamps,
  no randomness. An EXACT_MATCH + certified + all-known-headers result
  would carry warnings = [].
Consistency with J-T004-1 (trailing LF): canonicalMarkdown ends with a
  single LF (flattenGrid output used verbatim); compareMarkdown treats a
  missing/extra trailing LF as a byte difference, and analyze passes the
  flatten output straight through — no trimming, no re-joining — so the
  §6.3 markdown hash (83da5104… / e97edc1b…) matches T004/T005 exactly.

   Node-only calls. `npm run build` passes TODAY (exit 0, §1) ONLY because
   witness.ts is not yet in the bundle graph: index.ts mounts nothing until

   before mounting; do not mount first and debug later.

   If T009/T010 need a non-throwing report path for unsupported input, that
