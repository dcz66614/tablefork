本轮遇到的两个环境坑（供下次冻结参考）
--------------------------------------
 1. Node 24 的模块编译缓存：NODE_COMPILE_CACHE=0 不禁用缓存，而是把缓存目录
    当成字面相对路径 “0”——会在仓库根目录造出 0/node-compile-cache/（141 文件），
    被 computeSourceSet 扫进冻结集。正确做法：把 NODE_COMPILE_CACHE 指到仓库外
    的持久目录（如 $HOME/.node-compile-cache-p029），并在每次扫描前清空 .tmp-tmpdir。
    （第一次打包因此扫出 320/325 文件、写 ZIP 失败：artifacts/release/ 在 git rm
    旧 ZIP 后消失，dzip.py 打不开输出路径；已修：打包脚本先 mkdir -p。）
 2. vitest 会把 .tmp-tmpdir 里的解包副本也当测试跑：verify:release 在 .tmp-tmpdir
    下解包出的 tablefork-arc-*/tablefork-src-ex-* 含 tests/core 副本，
    随后 npm run test:core 会跑成 33 文件 / 2235 测试（= 745×3）。清理 .tmp-tmpdir
    后重跑恢复规范值 745/745（11 文件）。验收数以清理后重跑为准。
