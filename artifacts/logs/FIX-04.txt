§1. 核查：Oracle 是否确实含 \v（先核查，后动手）
------------------------------------------------------
oracle/reference.py:179：
    _ASCII_WS_RUN = re.compile(r"[ \t\n\r\f\v]+")
oracle/reference.py:183–189 normalize_text：
    folded = _ASCII_WS_RUN.sub(" ", decoded)
    return folded.strip(" \t\n\r\f\v")
结论：Oracle 的折叠正则与 strip 集合都含 \v。核查确认后 oracle/reference.py
一字未动（本卡只改 TS 一侧）。

修前 TS（src/core/parse.ts normalizeCellText）：
    .replace(/[ \t\n\f\r]+/g, ' ')
    .replace(/^[ \t\n\f\r]+|[ \t\n\f\r]+$/g, '')
结论：TS 折叠与 trim 字符集均为 [ \t\n\f\r]，漏 \v——与 Oracle 不一致，
含 \v 的单元格两侧会分歧（例：'\vhello\v'：TS 得 '\vhello\v'，Oracle 得 'hello'）。

§2. 修复（仅两个正则的字符集 + 注释）
---------------------------------------
src/core/parse.ts normalizeCellText：
    .replace(/[ \t\n\f\r\v]+/g, ' ')
    .replace(/^[ \t\n\f\r\v]+|[ \t\n\f\r\v]+$/g, '')
文件头裁决 5 的注释同步更新：ASCII 空白列举补“垂直制表符”，并注明 FIX-04
与 Oracle "[ \t\n\r\f\v]" 完全一致。normalizeCellText 上方的 JSDoc 原已写
Oracle .strip(" \t\n\r\f\v") 口径（FIX-03 留下），修后名副其实，无需改动。

规格口径：\v 属 ASCII 空白，与 PROJECT_BOOK.md §3.1 "ASCII 空白"一致——
无需改规格、无需改 docx、无需改 bundle、无需 Drive 操作、无需新增 Golden。

§3. 回归测试（tests/core/nbsp.test.ts，新增 6 用例）
------------------------------------------------------
新增 describe 'normalizeCellText folds/trims U+000B vertical tab (FIX-04)'：
1. 首尾 \v 被 trim：'\vx\v' → 'x'；'\v\v\vx\v\v' → 'x'；混合空格/\v 首尾 → 'x'
2. 单元格内连续 \v 折叠为一个 U+0020：'a\v\vb' → 'a b'；'a\v b'；
   'a \v\t\v b' → 'a b'（\v 与其他 ASCII 空白混跑同折）
3. 纯 \v 单元格归空：'\v\v' → ''；' \t\v\n\r\f ' → ''
4. FIX-03 不变：'\v\u00A0x\u00A0\v' → '\u00A0x\u00A0'（\v 去掉，NBSP 保留）；
   'a\v\u00A0b' → 'a \u00A0b'
5. 数值引用 &#11; 解码后同样处理：'&#11;x&#11;' → 'x'；'a&#11;&#11;b' → 'a b'
6. 端到端：'<td>\vhello\v\vworld\v</td>' 解析后 cell text 为 'hello world'
