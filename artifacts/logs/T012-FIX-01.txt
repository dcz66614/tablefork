§1 测法问题的原因（为什么全套超标不是产品问题）
--------------------------------------------------
T012 的全套 `npm run test:e2e` 用 2 个并行 Playwright worker 跑 21 条测试：
性能测试与另一 Chromium worker 在 1.5 共享 vCPU 上互争 CPU。原始数据
（T012-performance.json 五组数据集，见 §4）直接证明这一点：

- 全套 run A：p95 527.4ms（>500），但第 26–30 次耗时 144.9 / 203.2 /
  189.8 / 231.7 / 268.7ms —— 全部回落到独立运行区间；
- 全套 run B：p95 649.2ms（>500），但第 26–30 次耗时 210.4 / 166.5 /
  163.5 / 175.2 / 183.1ms —— 同样回落到独立运行区间；
- 两轮全套恰好都在后 5 次回落，对应另一 worker 跑完、CPU 争用消失。
  若产品本身慢，后 5 次不会系统性地回到独立区间。
- 独立运行 p95 263.2 / 282.8ms、Node 内核 p95 109.7ms，均以约 2 倍
  余量达标。测到的不是产品本身的速度，而是测试框架自身的并行争用。

结论：测量方法缺陷，不是产品缺陷。不动产品、不动阈值、不动表，
只把性能测量改为隔离串行运行。
