## 7. Documented judgement calls (spec does not pin these down; see parse.ts header)
J1. The frozen ErrorCode has only 7 codes and no INVALID_HTML / UNSUPPORTED_MARKUP.
    "No <table>", misplaced structure (multiple thead/tbody, misplaced tr/td,
    unclosed tags, stray text/elements outside the table) and elements outside
    the limited subset (<div>/<b>/<script>/<tfoot>/<colgroup> etc.) all map to
    INVALID_RAGGED_GRID with a message naming the real cause. This is the
    "grid cannot be formed in the limited subset" bucket, not a claim that the
    input is a ragged row. Needs T011 / final-review confirmation of the code.
J2. Multiple top-level <table> elements map to UNSUPPORTED_NESTED_TABLE
    (§3.1 "多 <table>、嵌套表格拒绝").
J3. scope="row" in thead and scope="col" in tbody are UNSUPPORTED_HEADER_SEMANTICS
    (contradictory header semantics). scope on <td> with row/col is ignored
    (no defined meaning); rowgroup/colgroup/invalid values on <td> are rejected.
J4. thead/tbody order is not enforced (at most one of each); span boundary is
    checked per covered row against its actual section. Bare <tr> under <table>
    is an implicit tbody row (HTML rule). <html>/<head>/<body> wrappers are
    rejected (not in the limited subset).
J5. Implicit close of td/th/tr/section at the next structural boundary follows
    the deterministic HTML rule and is accepted; EOF is not a boundary — any
    element still open at EOF is rejected. <caption> must be closed explicitly.
J6. Text normalisation: only ';'-terminated character references are decoded
    (named table in parse.ts; unknown names stay literal); consecutive ASCII
    whitespace folds to one U+0020 with trim; a single interior U+00A0
    (&nbsp;) is preserved as a deliberate character.
J7. headerStatus is KNOWN only when both row and column paths are non-empty;
    either missing means UNKNOWN. Per-slot paths are computed for every slot
    (including th-owned slots); which slots become SlotFacts is T008's job,
    as is the SHARED_SOURCE_CELL split for multi-slot cells.
J8. Rows/columns/cells count limits are checked in both parseValidatedTable
    (bytes, rows, DOM cells) and buildGrid (defensive re-check, plus columns),
    so each function is correct standalone and the pipeline rejects either way.
