## §5. 隔离性能 p95（32×12 表，30 次，目标 ≤500ms；T012-performance.json 六组旧数据未动）
# 方法：与 T012-FIX-01 相同的隔离串行项目（`npm run test:e2e:perf`，单 worker，
#   与功能测试永不同时执行）。本卡接线后的四次隔离测量：
# - 2026-11-21 ~04:22（本卡首次）：p95 286.0ms（n=30，min 171.1，p50 208.9，max 390.2）PASS。
# - 2026-11-21 ~04:31（验收序列内）：p95 515.9ms（n=30，min 161.7，p50 378.1，max 732.6）FAIL。
#   30 个原始值未保留：perf 测试每次运行覆盖同一文件 artifacts/logs/T012-perf-browser.json，
#   统计量（p50/p95/min/max）已记录如上。离群分析：同一代码、同一接线，
#   p50 从 ~209ms 翻倍到 378.1ms，且同期 e2e 全套耗时从 27.9s 涨到 37.3s、
#   取消探测耗时从 8–34ms 涨到 108–201ms——整机同时变慢，是共享 VM 的 CPU
#   争用（当时 load average 3.87，1.5 共享 vCPU），不是产品回归；代码在
#   两次运行之间一字未动。不改阈值、不改数据、不碰产品代码，按同一方法重跑。
# - 2026-11-21 ~04:33（重跑 1）：p95 373.8ms（n=30，min 172.8，p50 206.7，max 413.5）PASS。
# - 2026-11-21 ~04:33（重跑 2）：p95 312.7ms（n=30，min 181.0，p50 224.5，max 322.8）PASS。
# 结论：接线后隔离 p95 在 286–374ms 区间（余量约 1.3–1.7 倍），Worker 跳转
#   成本约 +30ms（对比接线前隔离 257.5ms）；515.9ms 为负载离群值，已如实
