## 2. SHA-256 实现来源与选择理由
- 来源：FIPS 180-4 SHA-256 规范手写实现（src/core/sha256.ts）。
  64 轮压缩函数，标准 K 常量（§4.2.2）与初始 H 值（§5.3.3），
  按规范逐字实现，无第三方依赖、无复制粘贴的外部代码库。
- 为什么不用 WebCrypto：witness 的见证搜索是同步的，
  crypto.subtle.digest 是异步的，无法直接替换。
- 为什么不用 node:crypto：项目书 §6.2 公共浏览器内核要求无 Node 专属调用；
  `import { createHash } from 'node:crypto'` 使 vite build 失败
  （`"createHash" is not exported by "__vite-browser-external"`，协调员已复现）。
- UTF-8 编码：TextEncoder（浏览器 / Node / Vitest 三处均有，与 Node 'utf8'
  编码一致：孤立代理项按 U+FFFD 计）。
- 本文件不 import 任何 Node 模块，不依赖 WebCrypto；
  浏览器 + Node + Vitest 三处都能跑。输出 hex 小写，签名 (text) => string，
  与原用法一致。
- 独立核对：实现写完后先用 /tmp/t009fix01-sha-check.ts 对照 Node createHash
  跑 13 例（含填充边界 55/56/63/64/119/120/128 字节、孤立代理项、代理对、
  CJK、emoji、100 万个 'a'），13/13 一致，exit 0，才接入 witness。

## 3. report.ts 的 WebCrypto 助手：二选一决定
- 决定：留作薄包装（不删除）。
- 理由：sha256Utf8WebCrypto 是已导出的公共助手，t008 临时测试
  （tests/core/t008-temp.test.ts）import 它；删除会断测试。
  新实现：`return sha256Sync(text)`，直接委托给共享同步函数，
  不再走 crypto.subtle.digest。analyze() 内部复核改用同一同步函数，
  不再依赖 crypto.subtle 在调用环境中存在。
- 诚实说明：复核现在与 witness 用同一实现算两遍——它仍能捕获
  “proof 与 canonicalMarkdown / A 图不一致”的装配错误，
  但不再是两个独立实现的交叉核对；与 node:crypto / WebCrypto 的
  等价性改由已知向量测试钉死（见 §4、§5）。
