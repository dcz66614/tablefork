## 7. 裁决小节（§7：未在规格中钉死的 e2e 细节）
- J-T012-1（生产构建与 preview 绑定）：T001 的 playwright.config.ts 原
  指 dev server（5173）；本卡要求跑生产构建，故 webServer 改为
  `npm run build && npx vite preview --port 4173 --strictPort --host 127.0.0.1`，
  baseURL 改为 http://127.0.0.1:4173。--host 127.0.0.1 是实测必需：本 VM
  上 vite preview 默认只绑 [::1]:4173，127.0.0.1 连不上（curl 返回 000），
  导致 webServer 首次启动 60s 超时；加 --host 后一次成功。另把
  trace 改为 retain-on-failure、screenshot 改为 only-on-failure（失败时
  保留截图与 trace，卡片要求；原 on-first-retry 在 retries=0 时永不触发）。
- J-T012-2（取消按钮真实不可达）：src/core/report.ts 的 analyze() 是 async
  签名、无真实 await，全程同步计算；App.tsx 的 runAnalysis 在 await 后才
  setAnalyzing(false)，React 把 true→false 批量合并为一次渲染，ANALYZING
  状态（“取消”按钮）在真实浏览器时序里不出现。3 次页内 1ms 轮询探测
  （32x12 最慢输入）均未观测到按钮。jobId 守卫改由竞态测试实证（两次
  连续分析取最新结果）。Worker 接线后（T010 的 Worker 已存在但 UI 未接，
  是 T013 的活）取消才可能真实可达，届时应重测。
- J-T012-3（Vitest 与 Playwright 文件后缀冲突）：Vitest 默认 include
  为 **/*.{test,spec}.*，会把 tests/e2e/*.spec.ts 当单测跑，Playwright
  的 test.setTimeout/beforeEach 在 Vitest 进程内抛错，导致 npm run test
  一度 exit 1（2 failed suites，719 单测本身全过）。修复：E2E 文件改名
  *.e2e.ts，playwright.config.ts 加 testMatch '**/*.e2e.ts'；未改
  vite.config.ts（不在本卡输出范围内）。改后 npm run test 恢复 719/719。
- J-T012-4（性能口径）：UI 耗时含 Playwright 开销（见 §6），与纯内核耗时
  不是同一口径，两者都如实列出；分位数用 nearest-rank（p95 = 第 29 个）；
  全套并行负载下的超标如实记 FAIL，不以独立运行的达标值替代验收结论。
- J-T012-5（截图哈希巧合）：T012-A-origin-empty.png 与
  T012-mobile390-A.png 的 SHA-256 与 T009 对应文件相同。原因是 UI 自
  T009 未变、同一 Chromium 对同一 DOM 确定性渲染；两文件由本轮两次
  Playwright 运行各写一次、哈希始终一致，不是复制 T009 的文件；C/D 两张
  哈希与 T009 不同。截图均为本轮新鲜截取（见 §3 尺寸与哈希）。
- J-T012-6（安全样本口径）：原始 <script>/<img> 标签在解析层即被拒
  （INVALID_RAGGED_GRID），这是“不执行”的第一道防线；实体转义样本证明
  恶意串以文本节点渲染；事件属性被解析器忽略且不进入渲染 DOM。三层
  各有一例，见 §4。
- J-T012-7（Blob URL 释放口径）：下载锚点在 click 后立即 remove，
  revokeObjectURL 在 1s 后（ExportPanel.tsx）；测试在 1.2s 后断言 DOM
  无 a[download]/blob: 链接。revoke 调用本身无法从外部直接观测，记为
  代码级（setTimeout revoke）+ DOM 级（锚点移除）双重证据，不谎称直接
  测到了 revoke。
- J-T012-8（平台）：WINDOWS_NOT_TESTED。CSP 与 Worker 兼容性：本卡未发现
  CSP 差异（页面零远程请求，见 §4）；Worker 线程未接入 UI（T010 的活，
  T013 集成），无从核对 CSP 与 Worker 的兼容性，记为 NOT_RUN，留待 T013。
