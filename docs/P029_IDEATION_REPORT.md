## 5. 八个通过门槛的候选：每项八项必填

### C01 表歧镜 TableFork｜复杂表格送给 AI 前的“同文异表”见证

- **目标用户：** 每周向 AI 粘贴网页/Office 转出复杂报价表的中文运营分析助理。
- **场景：** 工作日 19:00，Windows 笔记本浏览器；本地粘贴或导入 HTML 表格，并与准备发送给助手的 Markdown 比对。
- **痛点：** 假设每周 3 次，强度 5/5，每次失去 20–40 分钟逐格核对；当前做法是截图与手工写全标题，不能证明何种合并关系在转换后无法从文本恢复。
- **核心机制：** 确定性枚举表格合并网格、导出普通 Markdown，并构造另一个结构不同但在指定导出策略下生成**完全相同 Markdown**的表作为最小歧义证书；随后产出逐数据单元格的全路径纯文本交接稿。
- **最近方案+不同点：** `table2rules` 已做行列标题全路径输出；Docling 提供结构保真格式。C01 不复写其转换器卖点，新增原表/待发 Markdown 的逐项比对、可检验的非单射碰撞见证、最短歧义可视化和可重放 JSON。不是领域全球首创声明。
- **可行性：** TS/React/DOMParser/Worker + Python 标准库独立 Oracle；8–12 个工作日，全部合成 HTML/Markdown，浏览器本地运行、内存可清空、无模型/API、MIT；只支持 32×12 网格的 HTML 子集，不解析 PDF/DOCX。
- **最小验证：** 两张不同 HTML 表 A≠B，导出 F(A)=F(B) 的字节级断言；48 份手写 Golden、两种扁平化策略、200 个固定种子随机合法表；独立 Python Oracle 比对 100% 精确；250ms/32×12 为目标非实测。
- **风险/最大反对：** “既然表格转换器已有，为什么需要新工具？”答：碰撞的反例证据与逐格可核验交接，而不是另一种转换格式。若生成见证不能可靠验证或用户只需保存 HTML，价值减弱；无真人测试无法证明实际节省时长。

### C02 字节岔口 GlyphFork｜AI 修改中文技术文本前的精确匹配断点

- **用户/场景：** 中文 README 编辑者在笔记本上粘贴 AI 生成的 `old_string` 和本地原稿，执行替换前检查。
- **痛点：** 假设每周 6 次，强度 4/5，每次 5–10 分钟；肉眼看 `（）` 仍会误判，临时办法是全文搜索替换，可能误伤代码块。
- **机制：** 对两段字符串输出码点级最短失配区间，区分确切不相等、NFC 等价、形似字符、不可见差异，并生成不自动应用的精确替换候选。
- **先例+不同点：** `unicode-cleaner` 会清洗 Unicode；C02 以**两个完整编辑操作数**验证定位及替换是否能精确成功，并展示唯一匹配的目标区间与修复前后差集，不做泛化字符净化。https://github.com/mdbellouch/unicode-cleaner 。
- **可行性：** TS 原生字符串/Unicode 标准库；合成文本；无远程依赖、零现金、本地可删；不声称预测模型下一次生成。
- **实验：** 48 个固定 CJK/ASCII/不可见字符对 + 100 份种子字符串；预期匹配位置、UTF-16/码点区间与 Python Oracle 一致；不得误改正文。
- **风险/反对：** 编辑器自身已能高亮字符，可能产品价值低；必须把“真正执行 Edit.old_string 是否匹配”作为唯一独特验收点。Issue https://github.com/anthropics/claude-code/issues/52482 。

### C03 值形预警 TypeTripwire｜数字粘贴前的目标表格变形演示

- **用户/场景：** 中文行政资料员每周在 PC Excel 中整理 AI 生成的 CSV 编号列表。
- **痛点：** 假设每周 4 次，强度 5/5，每次 15–30 分钟，17 位编号失精度后难逆推；临时先设文本格式常忘记。
- **机制：** 本地按已文档化的有限“自动转换策略快照”模拟数字、前导零、指数形式和指定日期文本的转换前/后，逐列生成风险热图和 UTF-8 保真 TSV/JSON 导出。
- **先例+不同点：** Excel 官方已有预防设置；普通 Markdown→Excel 转换器存在。C03 不提供整套表格编辑，而是**数据尚未粘贴前的破坏见证**和目标策略的明确版本边界。https://support.microsoft.com/en-gb/excel/keeping-leading-zeros-and-large-numbers 。
- **可行性：** TS BigInt/字符串操作与有限状态转换；本地 CSV/TSV，成本 0；不能假装已在 Excel 真实执行。
- **实验：** 48 个强转案例、独立 Python 参考模型、所有身份证明字符串不丢；10,000 单元格内存预算为待验性能门槛。
- **风险/反对：** Excel 版本/选项繁多；仅模拟清楚声明的规则并标 `SIMULATED`，未覆盖行为一律 `UNKNOWN`。

### C04 话轮归属 VoiceTrace｜聊天摘录不能让建议冒充承诺

- **用户/场景：** 中文项目经理在 Windows 浏览器从结构化聊天导出 JSON 摘录交接 AI 协作任务。
- **痛点：** 假设每周 4 次，强度 5/5，每次 20–30 分钟；复制几段对话后角色前缀可能丢失；现在手动补“我说/助手说”，仍可能错段。
- **机制：** 从明确 `role/message_id` 的本地合成聊天 JSON 锚定原话片段，检查待发文本每句是否绑定原角色、是否有无出处引用；输出角色区间映射而非对话摘要。
- **先例+不同点：** ChatML/聊天导出可保留角色；未核实有同样的本地“摘录片段角色证明”产品。不同于 P011 对话续接摘要，C04 只做字符级出处归属。
- **可行性：** TS LCS/精确子串搜索，JSON 约束输入，0 API、纯合成；若同句不同人重复出现则标 `AMBIGUOUS`。
- **实验：** 72 段多说话人、重复语句、截取/重排 Golden；Oracle 断言角色不被臆断。
- **风险/反对：** 自由粘贴聊天不带元数据时无法推定角色，产品入口很窄；必须明确拒绝自动猜测。

### C05 单位折算尺 UnitBridge｜“万元”进入 AI 答案后量级不滑走

- **用户/场景：** 中文教育内容编辑在 PC 核对 AI 草稿的距离、时长、计数和金额单位表达（不输出投资建议）。
- **痛点：** 假设每周 3 次，强度 4/5，每次 10–20 分钟；人工心算可能漏 10³/10⁴ 因子；现用通用单位计算器但难关联原句位置。
- **机制：** 只识别固定显式数字+单位语法（如 `3.5万元`、`35000元`、`30%`、`0.3`），用有理数和维度表生成逐句等值/不等值证据与最短不一致对。
- **先例+不同点：** `Pint` 已能做科学单位换算；C05 专注中文文案跨句已标记数量的相互一致性，非通用换算器。https://pypi.org/project/Pint/ 。
- **可行性：** BigInt 有理数，无 NLP 语义判别；合成文本，0 API、MIT。
- **实验：** 60 个固定单元组合、独立 `fractions.Fraction` Oracle；不得把未声明单位的两个数字关联起来。
- **风险/反对：** 没有语义标签无法知道两句话是否描述同一事物；用户须指定需要比较的两处量。

### C06 忽略波纹 IgnoreRipple｜AI 改 `.gitignore` 前看哪批文件沉没

- **用户/场景：** 维护 JS 仓库的中文独立开发者在 PC 让 AI 增补 `.gitignore` 规则。
- **痛点：** 假设每周 2 次，强度 4/5，每次 15–25 分钟；现用 `git check-ignore -v` 逐路径检查，没有改动前后全部合成路径差集。
- **机制：** 输入合成文件树、旧/新 ignore 规则，在不运行 Git 仓库写操作情况下调用本地 Git 的 `check-ignore` 作权威判定，将“新增忽略/重新可见”按目录可视化并找最小触发规则。
- **先例+不同点：** Git 官方 `git check-ignore -v` 本身能查询匹配规则；C06 增量两套规则差分与树形热区，非 gitignore 解析器的原创宣称。https://git-scm.com/docs/git-check-ignore 。
- **可行性：** Node CLI + Git 本地子进程，仅操作测试临时目录，不访问真实仓库；Oracle 是 Git 的权威输出和独立快照。
- **实验：** 48 组 `!`、`**`、前缀规则；确保不写真实项目、diff 集合可重算。
- **风险/反对：** Git 原生工具已足够，非开发者群体受众窄；未证实 GitHub 大众传播。

### C07 链名分叉 LinkFace｜AI 读到的链接名与真正地址不同

- **用户/场景：** 中文技术课程作者每次将 HTML 产品列表转为 Markdown，再送给 AI 生成选型说明。
- **痛点：** 假设每周 2 次，强度 5/5，每次 15–25 分钟；现靠逐项悬停核对，但同名多链接时容易漏。
- **机制：** 从可信本地 HTML `<a>` 标签序列建立 `(可见文字, href)` 多重集，与待发 Markdown 的链接目标逐项比对；同文本指向多个目标时显示歧义，输出“不知道链接是否仍指向原始目标”证据。
- **先例+不同点：** Markdown link checker 主攻 URL 可达性；C07 不联网验证“活不活”，只验证**名称与目标在转换环节有没有错配**。
- **可行性：** DOMParser + Markdown 子集解析、本地、合成链接、0 访问目标 URL。
- **实验：** 48 组相同标题/不同 href/相对路径链接，精确多重集 Oracle，不能仅凭标题匹配位置。
- **风险/反对：** 转换工具自身可保留 href，担忧可能罕见；页面可能含跳转和 JS，本工具明确不跟随网络跳转。

### C08 跨盘命名 NameTransit｜AI 给出的文件树在不同系统存不下来

- **用户/场景：** 中文独立设计开发者用 Windows PC 接收 AI 批量生成的课程素材目录。
- **痛点：** 假设每月 3 次，强度 4/5，每次 10–20 分钟；名称在真正保存时被拒绝，回头改动链接；当前试保存一个个失败。
- **机制：** 导入一棵合成路径树，按明确目标 Windows/POSIX 文件命名子集做确定性判定、大小写折叠冲突检测，展示“第一个必失败路径”和最小冲突对，输出不自动重命名的建议清单。
- **先例+不同点：** `pathvalidate` 已有路径合法性函数；C08 对整棵 AI 建议目录树做多目标**相互冲突证明**，而非单字符串 sanitize。https://github.com/thombashi/pathvalidate 。
- **可行性：** TS 字符串、树、平台有限规则集；纯本地、零现金。
- **实验：** 80 个特殊名/大小写/尾空格组合，独立 Python pathvalidate 或标准规则 Oracle；Windows 不实跑时不能报告跨平台验证通过。
- **风险/反对：** 操作系统和文件系统有超多细节；只提供有限保守模型，不宣称等同目标 OS 的全部行为。
